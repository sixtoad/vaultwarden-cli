# Native CI fixture startup

[Run 37771997993](https://github.com/sixtoad/vaultwarden-cli/actions/runs/37771997993/job/113293584737) tested PR head `da18c625e6586cb3559695a5384250ef9c8cfc3e` and hit the unchanged 20-minute job limit. All 23 XCTest methods passed, but real URLSession tests spent 534 seconds across 15 fixture starts. Seventeen of twenty bundle cases passed before cancellation; successive cases took 35.244–35.357 seconds, including the HTTP-configuration rejection that performs no network request. The final three bundle cases, release build and final suite cleanup were not verified by that cancelled run. Saved logs/artifact and their hashes are alongside this record.

The synthetic Python HTTP server inherited `HTTPServer.server_bind`, which calls `socket.getfqdn` even for `127.0.0.1`. Fixture startup prints its port only after this unnecessary reverse-DNS lookup. The fixture now binds through `TCPServer.server_bind` and obtains its name/port directly from the bound numeric address. It remains threaded, loopback-only in the serving path, and uses the same TLS context, client-certificate requirement and request assertions. Production Swift/Rust transport, certificate validation, Keychain behavior and the CI time limit are unchanged.

The startup regression uses the actual serving path and a real listening socket while making both reverse-DNS APIs fail on use. TLS wrapping alone is replaced in this startup-only test; the full native suite retains real URLSession and all twenty signed-bundle TLS cases. Restoring the original HTTP server must fail this regression at runtime.

Local red/green and mutation results are recorded in `local-verification.json`. Hosted native validation runs on the resulting PR revision; its saved artifact is the authoritative source for all 23 Swift tests, 20 bundle cases and release build. See [PR #33 checks](https://github.com/sixtoad/vaultwarden-cli/pull/33/checks). No logged-in operator acceptance, app reinstall or synthetic provider session is performed by this CI-only correction. The separate final Mac approval gate remains pending.

The first retry (run37778663284) failed in the new regression because macOS rejects the `SO_ACCEPTCONN` socket option. The test now uses a real numeric-loopback connect/accept with one-second timeouts. This portable check passed on both Linux and the authorized Mac (Python3.9.6); restoring the original bind behavior failed at the intended reverse-DNS assertion on both. See `portable-mac-verification.json` and `portable-linux-verification.json`. Production code and the20-minute budget remain unchanged. Full hosted verification follows on this revision.
